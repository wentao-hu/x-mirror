GA4、GSC 和 Bing 配置教程

自建笔记建站开发

从零完成出海新站的 Google Analytics 4（GA4）、Google Search Console（GSC） 与 Bing Webmaster Tools（必应站长工具） 全套配置：创建 GA4 账号与数据流、将 G- 衡量 ID 写入站点代码并部署、无痕窗口触发 Cookie 同意与实时报表验证、将留存期延长至 14 个月、通过 Cloudflare 一键授权验证 GSC 域名所有权、提交 sitemap.xml、将 GSC 与 GA4 双向关联，最后在 Bing Webmaster Tools 直接从 GSC 一键导入站点并补交 sitemap.xml。

核心原则：代码接入只需要 G- 开头的衡量 ID（如 G-BL3MDRQG5G），不要贴整段 gtag 代码，也不要装 Google Tag Manager。 站点模板已内置 Consent Mode v2 隐私横幅，仅在访客点击 Accept 后才加载 gtag.js 并发送 collect 请求（返回 204）。

完成标准（7 项全部打勾才算跑通）： ① site.ts 填入 ga4Id 并完成 npm run build && npx wrangler deploy；② 无痕窗口（确保未启用 AdBlock/uBlock 扩展）点 Accept 后 Network 出现 collect?v=2...（状态码 204）；③ GA4「实时概览 / 页面实时浏览情况」能看到活跃用户 ≥ 1；④ GA4 事件与用户数据保留期均改为 14 个月并保存；⑤ GSC 通过 Cloudflare 一键授权验证网域并提交 sitemap.xml；⑥ GA4「产品关联 → Search Console 关联」显示绿色的链接已创建；⑦ Bing Webmaster Tools 从 GSC 一键导入站点，并在 Sitemaps 页面手动补交 https://<domain>/sitemap.xml 直至状态显示绿色的 Success。

1. 创建 GA4 账号与媒体资源（已有主账号直接新建「媒体资源」）

打开 analytics.google.com。多网站重要原则： 如果你的 Google 账号下已经有 GA4 顶层账号（如 Hit The Road Dude AI 主账号），做第 2、第 3 个新网站时不要每次都新建顶层账号，而是直接点左下角齿轮 管理（Admin） → 左上角 + 创建 → 选择「媒体资源（Property）」 跳到 1.2 节即可。只有当你第一次用 GA4、名下还没有任何账号时，才从 1.1 节的创建账号开始：

1.1 账号名称：填品牌名，不要填个人邮箱

账号是顶层容器（一个账号下可挂多个站点的媒体资源）。建议填品牌名（如 Hit The Road Dude AI），不要填个人 Gmail 邮箱，也不要留默认占位文字。

图注：创建账号页：账号名称填品牌名（如 Hit The Road Dude AI），下方数据共享设置保持默认即可。

媒体资源对应单个网站。名称直接填域名 hittheroaddudeai.fun，报告时区选美国洛杉矶，币种务必选 美元 (USD)。

图注：创建媒体资源页：名称填域名，时区选美国洛杉矶，币种选美元（USD）。

图注：商家详情页：选「艺术与娱乐」与「小型 - 1 至 10 名员工」。

业务目标决定左侧导航默认生成哪些预设报表。推荐勾选「发掘潜在客户」与「提高销售额」（即使四个全勾也不会报错，保持现状即可，无需回头修改）。

图注：业务目标页：决定左侧菜单预设模板，不影响底层事件采集。

1.5 接受服务条款与 GDPR 数据处理条款

弹窗中勾选「按照 GDPR 的要求，我也接受《数据处理条款》」，点击 我接受 进入数据流配置。

2. 配置网站数据流与增强衡量（向导第 5 步）

平台类型选择 网站（Web），输入正式域名 hittheroaddudeai.fun，数据流名称填 Web — hittheroaddudeai.fun，保持「增强型衡量」开启。

图注：设置网站数据流：填好正式域名与数据流名称，点击右侧齿轮可查看增强型衡量项。

2.1 增强型衡量：千万不要关掉第一项「网页浏览量」

点开增强型衡量齿轮可以看到 7 个开关。第一项 网页浏览量（Page views） 置灰且圆点在右侧，代表它是默认常开的基础项（SPA 路由跳转全靠它统计 page_view）。如果没有站内搜索框，可以把「网站搜索」关掉，其余保持默认开启即可。

图注：增强型衡量面板：第一项「网页浏览量」圆点在右代表已开启；无站内搜索时可关掉「网站搜索」。

2.2 关掉顶层代码抽屉、复制 G- 开头的衡量 ID（忽略顶部黄色警告）

点击「创建并继续」后，页面往往会连续弹出两层抽屉：最上面第一层是「设置 Google 代码（含手动安装 / GTM 说明）」抽屉，直接点它左上角的 × 关掉；关掉后露出的第二层就是下图的「网站数据流详情」抽屉，里面同时展示「数据流 ID（纯数字）」和「衡量 ID（G- 开头）」。我们只需要复制右上角 G-BL3MDRQG5G 这个衡量 ID，然后再点左上角 × 关掉这层抽屉，就能点到底部的「下一步 → 继续前往首页」。此时顶部提示「您的网站尚未启用数据收集功能」属于完全正常的初始状态。

图注：网站数据流详情页：只需复制右上角 G- 开头的衡量 ID（G-BL3MDRQG5G）；顶部黄色提示在站点接入收到数据后会自动消失。

拿到 G- 衡量 ID 后，回到站点仓库修改 src/config/site.ts 中的 analytics.ga4Id，然后执行部署：

// src/config/site.ts

3.1 无痕窗口打开网站并点击 Accept（避开 uBlock AdBlock 拦截坑）

部署完成后，用未安装广告拦截插件的纯净浏览器打开无痕窗口访问 https://hittheroaddudeai.fun（重点避坑： 切勿使用带 uBlock Origin / AdBlock 的浏览器如 Ego Browser 去测 GA4 上报，因为拦截插件会把 gtag/js 静默替换为空函数桩，导致点了 Accept 也发不出任何 collect 请求）。此时页面底部会自动弹出 Analytics cookies 隐私同意横幅，必须点击 Accept 按钮——站点遵循 Consent Mode v2，在访客点同意前不会加载 gtag.js。

图注：无痕窗口访问首页自动弹出 Analytics cookies 横幅，点击 Accept 才会加载 GA4 脚本。

3.2 检查浏览器 Network 面板确认 204 上报成功

按 F12（或右键检查）切到 Network（网络） 面板，在过滤框输入 G-BL3MDRQG5G。只要看到两条记录：① js?id=G-BL3MDRQG5G 状态码 200（脚本加载成功）；② collect?v=2&tid=G-BL3M... 状态码 204（数据已成功送达 Google 服务器），就证明前端上报已经 100% 跑通。

图注：Network 面板出现 js?id=G-BL3MDRQG5G (200) 与 collect?v=2... (204)，代表浏览器已将访问事件发给 Google。

3.3 为什么点完 Accept 却在 GA4「报告概况」里看不到数据？

实操高频误区： 很多时候看 Network 明明已经有 204 请求了，但切回 GA4 点左侧「报告」却只看到下图「创建报告概况（选择模板）」，以为没收到数据。其实是因为当前停在了「报告概况」（非实时汇总报表需要 24–48 小时才会出数），还没点进它下方的实时概览或页面实时浏览情况。

图注：停在「报告概况」看不到实时访问（这里顺手点左侧「用户行为 → 选择此模板」即可）；看实时数据要点左侧菜单第二项「实时概览」或第三项「页面实时浏览情况」。

3.4 切到「页面实时浏览情况」确认活跃用户为 1

点击左侧菜单的 实时概览 或 页面实时浏览情况，立刻就能看到「活跃用户 1、浏览次数 1」以及受访路径 /。看到这个画面，说明 GA4 从网页端到 Google 后台已经彻底调通。

图注：切换到「页面实时浏览情况」后，立即可见活跃用户 1 和首页浏览记录，确认 GA4 彻底跑通。

4. GA4 后台收尾：数据保留期改为 14 个月

GA4 默认只保留 2 个月的明细数据。调通实时数据后，顺手点击左下角齿轮 管理 → 数据收集和修改 → 数据保留，把「事件数据」和「用户数据」的保留期限全部从 2 个月改成 14 个月，保持「有新的用户活动时重置」开启，最后点击左下角蓝色的 保存 按钮。

图注：将事件数据与用户数据保留期限均改为「14 个月」，改完务必点左下角蓝色的「保存」按钮使其生效。

至于 sign_up（注册）、generate_video（生成视频）、purchase（购买）这三个核心转化事件，等后续站内真实触发过一次后，再去「管理 → 数据显示 → 事件 / 关键事件」里把它们勾为关键事件即可；Google Signals 与广告关联现阶段保持不开启。

5. 配置 Google Search Console（GSC）并提交站点地图

GA4 负责统计站内用户行为，Google Search Console（GSC）则负责监控网站在 Google 搜索结果里的收录、曝光词和点击量。GA4 调通后紧接着配置 GSC。

5.1 添加「网域」资源（涵盖全部子域与协议）

打开 search.google.com/search-console，在「请选择资源类型」弹窗中选择左侧的 网域（Domain），输入裸域名 hittheroaddudeai.fun（不带 https:// 和斜杠），点击 继续。

图注：选择左侧「网域」资源类型，输入裸域名 hittheroaddudeai.fun 后点继续。

5.2 跳转 Cloudflare 点击 Authorize 一键写入 TXT 记录

点击开始验证后，GSC 会自动识别域名托管在 Cloudflare 并跳转到 Cloudflare 授权页（Authorize DNS records from Google）。直接点击蓝色的 Authorize 按钮即可——它会自动帮你把 google-site-verification=... 的 TXT 记录写进 DNS，省去手动复制粘贴。

图注：跳转到 Cloudflare 后直接点蓝色的 Authorize，自动完成 DNS TXT 验证记录写入。

5.3 完成所有权验证并进入资源页面

点完 Authorize 后会自动跳回 GSC，弹出绿色的「已完成所有权验证」，点击右下角 前往资源页面。

图注：所有权验证通过，点击「前往资源页面」进入 GSC 控制台。

5.4 提交 Sitemap 站点地图

在 GSC 左侧菜单点击 编制索引 → 站点地图（Sitemaps），在「添加新的站点地图」输入框填入完整地址 https://hittheroaddudeai.fun/sitemap.xml，直接点击右侧蓝色的 提交。

图注：在「站点地图」页填入 https://hittheroaddudeai.fun/sitemap.xml 并点「提交」。

5.5 提交成功后的「无法抓取」假报错说明与「测试实际网址」实时验证

提交后会弹出「已成功提交站点地图」。注意看弹窗背后表格里有时会显示红色的「无法抓取」（且「上次读取时间」为空）——这是 GSC 对刚验证新域名的异步排队假报错（Google 把新域名的 Sitemap 放进后台低优先级队列，在首次拉取前统一显示「无法抓取」，几小时到 2–3 天会自动变为绿色的「成功」）。当场自证方法： 直接在 GSC 顶部搜索框输入 https://hittheroaddudeai.fun/sitemap.xml 按回车 → 点击右上角 「测试实际网址（Test Live URL）」 让 Googlebot 实时抓取一次，只要返回绿色的「网址可编入 Google 索引 + 网页可以编入索引」，就证明 Sitemap 100% 正常。

图注：站点地图提交成功；若背景列表刚提交时显示红色「无法抓取」，关闭弹窗刷新页面即恢复正常。

6. 将 Search Console 关联回 GA4（打通自然搜索报表）

最后一步是把刚建好的 GSC 关联到 GA4，这样在 GA4 里也能直接查看自然搜索词与落地页表现。回到 GA4 左下角 管理 → 产品关联 → Search Console 关联，点击右上角蓝色的 关联。

6.1 第 1 步：选择刚验证的 Search Console 媒体资源

点击「选择账号」，勾选刚才验证通过的 hittheroaddudeai.fun（资源类型为「域」），点击右上角蓝色的 确认，然后点「下一步」。

图注：第 1 步：勾选 hittheroaddudeai.fun 域资源，点右上角「确认」。

6.2 第 2 步：选择对应的网站数据流

点击「选择」选中 Web — hittheroaddudeai.fun 数据流，然后点击蓝色的 下一步。

图注：第 2 步：选中网站数据流 Web — hittheroaddudeai.fun 后点「下一步」。

6.3 第 3 步：检查并点击「提交」

进入第 3 步「检查并提交」预览画面后，核对上下两项均为当前站点，务必再点一次底部的蓝色「提交」按钮才算真正落盘。

图注：第 3 步：核对媒体资源与数据流无误后，点击底部的「提交」按钮。

6.4 确认显示绿色的「链接已创建」

提交完成后，页面右侧显示绿底标签 链接已创建，至此 GA4 与 Google Search Console 的全套配置与双向关联就 100% 搞定了。

图注：看到绿色的「链接已创建」，代表 GA4 与 GSC 已全部配置完成并打通。

7. 配置 Bing Webmaster Tools（从 GSC 一键导入 + 手动补交 Sitemap）

Google Search Console 配好后，顺手把 Bing Webmaster Tools（必应站长工具） 也一起开通。Bing 不仅带来必应搜索流量，也是 ChatGPT Search、Microsoft Copilot、DuckDuckGo 等 AI 搜索引擎的核心底层索引源。因为站点已经在 GSC 验证过，千万不要选右侧手动添加（不用再配一次 DNS TXT），直接复用 GSC 验证结果一键导入最快。

7.1 打开 Bing Webmaster Tools，点击左侧「Import from GSC」

打开 www.bing.com/webmasters 并登录微软账号（或 Google 账号）。如果是第一次进入，会看到下图左右两栏欢迎页，直接点击左侧 Google Search Console 卡片下方的蓝色 Import 按钮；如果之前已经添加过其他站点，则点击左上角站点切换下拉框最底部的 Add a site（添加站点），同样选择从 GSC 导入。

图注：欢迎页直接点左侧「Import your sites from GSC」下方的蓝色 Import 按钮，免去重复做 DNS 验证。

7.2 授权 Google 账号并勾选要导入的站点

在弹出的 Google 授权窗口中选择你刚配置 GSC 的同一个 Google 账号并允许读取权限。随后右侧滑出「Import from Google Search Console」抽屉，列出你名下已验证的全部 GSC 站点，勾选目标站点后点击右下角蓝色的 Import 按钮即可秒级完成导入。重点避坑： 注意看表格里的 Sitemaps Count 一栏经常显示为 0——这是因为 GSC 里刚提交、还处于异步排队初始态的 Sitemap 不会被 Bing 自动同步过来，所以导入完成后必须手动去补交一次 Sitemap。

图注：勾选要导入的站点并点右下角 Import；注意 Sitemaps Count 显示为 0，说明站点地图未自动带入，稍后需手动补交。

7.3 导入成功后进入左侧 Sitemaps 页面

导入完成后进入 Bing 站点控制台首页，顶部横幅同样提示 meanwhile, to speed up the indexing process, please submit your sitemap by using the Sitemaps feature。先在左上角下拉框确认当前选中的站点（若有多个站点，需逐个切换操作），然后点击左侧菜单的 Sitemaps（或首页中间的 Sitemaps 卡片）。

图注：导入后的控制台首页：左上角可切换不同站点，点击左侧 Sitemaps 进入站点地图管理页。

7.4 点击 Submit sitemap 填入完整站点地图地址

在 Sitemaps 页面点击右上角蓝色的 Submit sitemap 按钮，在弹窗输入框中填入完整 URL（例如 https://glowupai.tech/sitemap.xml 或 https://hittheroaddudeai.fun/sitemap.xml，注意必须带 https:// 且与左上角当前选中的域名严格一致），点击蓝色的 Submit。

图注：点击右上角 Submit sitemap，在弹窗中输入 https://<你的域名>/sitemap.xml 并点击 Submit。

7.5 确认 Sitemap 状态变为绿色的 Success 并发现 URL

Bing 抓取 Sitemap 的速度比 GSC 快得多，通常提交后几秒内（刷新一下页面），Status 就会从 Processing 变成绿色的 Success，同时上方统计卡片会立刻显示 Known sitemaps: 1、Sitemaps with errors: 0 以及实际解析出的页面数量（如 Total URLs discovered: 11）。如果有多个站点，在左上角下拉框切换到下一个站点，重复 7.4 节补交它的 sitemap.xml 即可。

图注：提交后数秒即显示绿色 Success 与 Total URLs discovered: 11，代表必应站长工具与 Sitemap 收录配置 100% 完成。

需要复制整段 gtag 代码或装 Google Tag Manager 吗？不需要，项目已内置带 Cookie 同意控制的注入逻辑只需把 G- 开头的衡量 ID 填入 src/config/site.ts 的 analytics.ga4Id 并运行 npm run build && npx wrangler deploy
点了 Accept 之后，为什么 Network 里既没有 gtag/js 也没有 collect (204) 请求？当前浏览器装了 uBlock Origin / AdBlock 扩展（如 Ego Browser 内置 uBlock），把 gtag/js 静默替换成了空函数换用未开广告拦截的纯净 Chrome 无痕窗口测试；若用 Playwright 自动化测试，需去掉 HeadlessChrome UA 标识以免被 GA4 当成机器人过滤
无痕窗口点了 Accept、Network 也有 204，为什么「报告概况」没数？当前停在非实时的「报告概况」（汇总表需 24–48 小时），没点进实时页点左侧菜单的 实时概览 或 页面实时浏览情况，立刻能看到活跃用户 1
增强型衡量第一个「网页浏览量」是灰色的，是不是没开？不是，圆点在右侧代表它是默认常开的基础项保持原样不要动；关掉会导致 SPA 路由切换丢 page_view
数据流顶部提示「网站未启用数据收集功能」怎么办？新建数据流尚未收到线上上报时的默认提示不用管；站点部署并触发一次 Accept 后，实时报表先出数，黄条会在 48 小时内自动消失
GSC 点开始验证后跳到 Cloudflare，直接点 Authorize 吗？Google 识别到 Cloudflare DNS 后提供的一键 OAuth 授权直接点蓝色的 Authorize，它会自动添加 TXT 验证记录，无需手动复制粘贴
GSC 提交 sitemap.xml 后列表显示红色「无法抓取」（上次读取时间为空）？GSC 对刚提交的新域名 Sitemap 的异步排队假报错（后台队列尚未首次拉取）在 GSC 顶部网址检查框输入 https://<domain>/sitemap.xml 点「测试实际网址」，返回绿色「网址可编入 Google 索引」即确认正常，等后台队列排到自动变绿
Bing 从 GSC 一键导入站点时显示 Sitemaps Count 为 0，还需要手动提交吗？GSC 里刚提交的 Sitemap 处于异步排队初始态，Bing 导入接口拿不到未完成首次抓取的 Sitemap导入完成后点左侧 Sitemaps → 右上角 Submit sitemap，手动填入 https://<domain>/sitemap.xml 提交，几秒内即变绿 Success
Cloudflare 2.5k 访问、后台 44 会话、GA4 数字为什么对不上？三者统计口径不同：Cloudflare 含爬虫与边缘请求，后台计站内业务会话，GA4 只计点过 Accept 且未开广告拦截的浏览器各司其职：看收入订单用后台，看真人渠道趋势用 GA4，看总请求与爬虫用 Cloudflare，看搜索词收录用 GSC / Bing
